# Cua Driver learnings

The canonical cross-backend limitation record, including reproduction commands
and issue ownership, is [`BACKEND-LIMITATIONS.md`](BACKEND-LIMITATIONS.md).

- Cua Driver 0.10.0 is a host-native macOS driver, not a VM. `launch_app` attaches/launches without intentionally fronting the app, and accessibility actions default to background delivery.
- `get_window_state` is authoritative for each action turn. Its `element_index` and `element_token` are ephemeral and replaced by a fresh snapshot; neither is cached.
- The cache stores only durable grounding: concept/query, role, sanitized distinctive UI tokens, actions, ancestor roles, and relative geometry, keyed by app, window, scope, and structural match. It never stores pid/window IDs, snapshots/screenshots, ephemeral handles, live values, or extracted data.
- On a cache miss, `CachedCua` gives Pi bounded current AX candidate views plus the current screenshot. Candidate IDs are request-local; CUA indices/tokens are not sent to Pi or cached. Screenshots and live labels/values are inference context only and are never replay artifacts.
- For this project, CUA's main advantage over Simulang is its explicit background AX delivery for elements that expose actions. Outlook's message rows expose no AX actions. A durable row action therefore snapshots again, resolves its container-scoped position, converts its current AX frame to window-local screenshot pixels, dispatches once in the foreground, and verifies fresh Reading Pane extraction before continuing. A point found only from pixels can run once but is not cached.
- CUA can expose Outlook's `AXTable "Message List"`, row cells, and `AXWebArea "Reading Pane"`; one controlled run selected rows and read three live pane bodies. Outlook can also intermittently produce a recursive menu-only tree: CUA returned 3,961 menu elements and no Message List even with lower depth limits. The demo classifies that as a safe environmental failure and never fabricates email results or attempts a blind pixel click.
- Outlook conversation summaries and individual messages share the same table. The compiled workflow uses container-scoped positional identity for “top N” operations because message labels are live data and duplicates are valid. It requires exactly three non-empty, non-duplicate live extraction results and checks that repeated selections change the extracted pane data.
- Conclusion: CUA is the better Outlook backend when its window-rooted AX snapshot is healthy, but non-focus-stealing row activation is unavailable for Outlook's actionless cells. The most useful upstream CUA improvement is cycle/deduplication plus a reliably window-rooted AX traversal; screenshot/vision grounding remains the fallback for custom-drawn controls.
