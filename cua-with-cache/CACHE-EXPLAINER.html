02 / Key

What names a cache entry?

The filename is not a fuzzy UI fingerprint. It is a stable hash of the requested operation and reusable app context.

Action key

Canonical JSON → SHA-256

  1. Collapse whitespace and lowercase the semantic instruction.
  2. Scope it to the stable bundle ID and normalized window title.
  3. Separate operation kinds so plans, actions, and extractions cannot collide.
  4. Serialize recursively with object keys sorted, then hash.
Variables: action keys include sorted variable names, not their runtime values. An operation can be reused with different substitutions.

04 / Dispatch

AX identity; two ways to click

CUA snapshots contain serializable element records, not live node objects. Dispatch depends on whether the current AX element exposes a press action.

Element supports AXPress

Accessibility dispatch

descriptor→fresh element→fresh token/index→AX press

CUA Driver receives the freshly resolved element token or index with background delivery. The ephemeral handle is never cached.

Element has actions: []

Frame-derived coordinate dispatch

Common for Outlook message rows. AX identifies the row; its current frame is converted to screenshot coordinates for one foreground click. No absolute point is cached.

Visual-only fallback: if Pi can find a target only in the screenshot, it may dispatch a ratio-based point for that run. Because it has no durable AX identity, cacheable: false.
05 / Replay

A hit is resolution, not blind playback

1

Read fresh structure

Snapshot the current window. Cached process IDs, window IDs, and previous tokens play no role.

2

Re-resolve and validate

Check scope, role, identity tokens, ordinal, structural endpoint, and uniqueness as applicable.

3

Replay or heal

Unique match: dispatch without Pi. Missing or stale: ask Pi once to compile a replacement. Unsafe: fail closed.
