Project overview

A compiler for repeatable GUI work.

Agents author small semantic workflows. Pi resolves unfamiliar GUI operations once. The cache compiles those choices into validated replay data, then runs warm paths deterministically without another model turn.

Not a recording. Not an agent loop.

The product caches reusable operations and grounding—not screenshots, generated source, stale handles, or returned application content.

01 / Vision

Meaning in. Safe replay out.

The final interface should be simple enough that workflow authors describe intent and schema, while the library owns traversal, grounding, validation, input delivery, persistence, and healing.

What the agent writes

One task, one schema

  • No raw CUA tokens, Simulang nodes, or mouse coordinates.
  • No external coding agent when a cached step is stale.
  • No Outlook semantics inside the generic library.
  • Live email values are outputs, never grounding cache entries.
Cache hit → replay directly.
Cache miss or stale step → invoke Pi internally, compile, validate, update, continue.

Workflow ordering and loops remain ordinary JavaScript. Pi supplies model turns only for missing or stale operations; its TUI and coding-agent loop are not part of runtime self-healing.

02 / Stagehand

Borrow the compilation boundary

Stagehand does not remove site-specific intent. It converts a semantic browser operation into bounded structured replay data. Native GUI automation needs the same boundary with a different selector language.

Browser · Stagehand

DOM locator + operation

On a miss, a model examines the DOM and selects an element and supported method. A hit resolves the locator against the current DOM and executes without another grounding turn.

{ selector: "xpath=…",
  method: "click",
  arguments: [] }
≈
Native GUI · gui-cache

AX descriptor + operation

Pi selects one bounded current-UI candidate. The library compiles stable role, scope, ordinal, tokens, method, and delivery metadata—never generated JavaScript.

{ descriptor: { role: "AXCell", scope: "Message List", ordinal: 2 },
  method: "click", addressing: "pixel" }

03 / Runtime

Explore miss, hit, and healing

A hit skips inference—not fresh-state resolution or validation. Once dispatch may have happened, the runtime never blindly retries.

1

Build key

Instruction, operation kind, app, route, schema, or variable names.

2

Lookup artifact

Read workflow, action, or extraction JSON by stable SHA-256 key.

3

Fresh UI

Read bounded AX structure; include a screenshot only when grounding needs it.

4

Ask Pi

Select an offered target or compile a bounded recipe. Validate the result.

5

Resolve + dispatch

Use a fresh token/frame. Prefer AX; use one foreground click when required.

6

Verify + commit

Observe the outcome, return live data, and persist only reusable structure.

MISS

No artifact exists. Pi resolves the missing operation, and validated replay data is stored.

04 / Cache

Operations compile independently

Imperative workflow code is the source of ordering. Action and extraction artifacts remove repeated model turns while every app result is read live.

Optional planning cache

Only for cua.execute()

  • Default: imperative JavaScript; no workflow plan is needed
  • Optional: stores agent-planned act/extract ordering
  • Commit: after the autonomous workflow output validates
{ "steps": [
  { "kind": "act", "scope": "outlook", "instruction": "Open first message" },
  { "kind": "extract", "scope": "outlook", "instruction": "Read sender, subject, body" }
] }
Grounding cache

Target + operation

  • Stores: durable descriptor, method, addressing
  • Removes: repeated target grounding
  • Never stores: token, index, PID, window ID, absolute point
{ "method": "click",
  "target": { "role": "AXCell", "scope": "Message List", "ordinal": 2 },
  "addressing": "pixel", "deliveryMode": "foreground" }
Reading cache

Live field recipe

  • Stores: root descriptor, structural field paths and roles
  • Removes: repeated field grounding
  • Never stores: sender, subject, body, or screenshot
{ "root": { "role": "AXWindow", "tokens": ["inbox"] },
  "fields": [
    { "name": "sender", "path": [36], "source": "value" },
    { "name": "body", "path": [43], "source": "subtree_text" }
  ] }

07 / Lessons

The cache is an execution policy

Correctness comes from boundaries around inference, identity, dispatch, verification, and persistence—not from storing more UI state.

Acceptance ≠ success

A backend accepting input does not prove the intended UI outcome. Verify fresh state.

Uncertain dispatch is terminal

Never heal or retry after input may have happened; that risks duplicate actions.

Identity has semantics

“First row” follows position; a keyed item must remain uniquely identifiable.

Completion must be proven

No settled extraction change can mean a boundary, lost focus, latency, or stale structure. The current all-Inbox demo reports this as incomplete.

Serialization is deliberately lossy

Bound depth, nodes, and text. Convert stale getters to safe JSON values.

Privacy begins at descriptors

Sanitize labels and tokens before persistence, not only returned values afterward.

08 / TODOs

Next capabilities, without widening the API

Keep workflow code simple. Add power beneath the compilation boundary.

01

Coordinate → durable AX identity

Hit-test a Pi-selected visual point back to an AX element. Cache it only when the element has durable identity and matches the visual target.

02

One backend-independent element.click()

Resolve fresh, prefer semantic AX action, otherwise click a validated point in the current frame.

  • Do not assume AX press and coordinate click are equivalent.
  • Account for focus, pointer movement, occlusion, scaling, and conversion.
  • Never fall back after an uncertain AX dispatch.
  • Use workflow risk and postconditions to decide whether fallback is safe.
03

Bounded see()

Return a compact AX view when small, or a screenshot when structure is huge. Prefer keyword-scoped AX search over asking a model to inspect an unbounded tree.

04

Harden Simulang traversal

Use breadth-first search or a DFS-to-BFS fallback, deduplicate candidates, and surface node-budget exhaustion.

05

Cross-scope data flow

Bind named live extraction outputs from one app into later actions in another app without persisting those values in workflow or action caches.
