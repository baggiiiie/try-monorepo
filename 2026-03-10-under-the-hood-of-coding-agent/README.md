to run:
```bash
GROQ_API_KEY=<GROQ_API_KEY> bunx tsx agent.ts
```

## request

I know that for each request to model it contains all the information of the previous messages. 

What I didn't realize is, even between each two calls it models reasoning, this is happening too.  
Every iteration of the while loop sends the **entire `messages` array** plus the full tools definition to the Groq API. 

```ts
  while (iterations++ < MAX_ITERATIONS) {
    const response = await groq.chat.completions.create({
      model: MODEL,
      messages,
      tools,
      tool_choice: "auto",
      temperature: 0.6,
      max_completion_tokens: 4096,
    });
    // other code
```

This is how the Chat Completions API works, it's stateless. The server doesn't remember prior turns, so the client must send the full conversation history and tool schema on every request. The cost (in tokens and latency) grows with each iteration.
